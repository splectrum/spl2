# The Stack - Vertical View

## Layers

```
        HAICC (soaks down)
            ↓
    ┌───────────────────┐
    │    Splectrum   ←──┼──→  Mycelium
    │   (apps/API)      │    (data/structure)
    └───────────────────┘
            ↓
    Physical units (data + functionality)
            ↓
         P2P distribution
```

**Not clean slices** - layers interpenetrate:
- HAICC principles soak into Splectrum
- Splectrum and Mycelium penetrate each other (dual penetration)

## The Layers

**HAICC** - Methodology expressed within the platform. Not a technical layer.

**Splectrum** - Apps/API model. Horizontal DSL vocabulary ties it together.

**Mycelium** - Thick layer, still evolving:
- Multiple data APIs (stream, transactional, document, mycelium-native)
- Logical structure built with containers
- Patterns map directly into Splectrum through data API equivalence

**Physical units** - Containers carrying both data AND functionality.

**P2P** - Distribution layer (Pear/Bare foundation).

## The Bridge

Splectrum ↔ Mycelium linkage:
- Apps/API model connects to mycelium structure
- Data API equivalence provides the mapping
- DSL glossary gives horizontal coherence

## Container (Young Concept)

Containers are the universal unit - still being specified.

Each layer sees containers through its own lens:
- Distributable into P2P
- Linkable through mycelium web
- Typed and API-bearing in Splectrum
- Work packages in HAICC

The data/functionality dualism lives in the container itself.
