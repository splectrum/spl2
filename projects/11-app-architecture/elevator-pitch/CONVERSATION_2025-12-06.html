Three modes, seamless transitions: - Free scripting - Quick, exploratory, functional - Stateless API - Request/response, pure processing - Stateful Apps - Persistent state, lifecycle

Vertical Structure

  • Logical structures (1:1 with API)
  • Physical structures (1:many from logical)
  • Inheritance with full lifecycle
  • Dev seamlessly integrated
  • Migration built in

Horizontal Coherence

DSL glossary/vocabulary ties it together - same terms, same meanings across domains.

Language Evolution = Capability Expansion

The DSL isn’t static - it evolves. As language matures: - New concepts become expressible - Complex patterns become simple terms - AI can do more with less instruction

Language evolution is the primary driver of increased capabilities.

6. Mycelium

The Physical Layer

Immutable containers + Mutable indexes
              │
    Mycelium web spidering (linking)
              │
    Data APIs (stream, transactional, document, mycelium-native)

Why P2P Fits Naturally

Not forced - structural alignment:

  • Immutable containers created within local transaction context
    • Like a project: add/update until closure → immutable (won’t change)
    • Content-addressable once closed
  • Local ownership
    • Like microservice owning its data
    • Read access to outside world, write access local
  • Spidering enables distributed discovery
    • Links between containers across nodes
    • Discoverable (Pear platform has deep support for this)

The Web

entrypoint → context (self-describing) → next entrypoint → ...

Information flows like nutrients. No central directory.

Integration Fabric

  • Self-contained units that link together
  • Data + functionality in same container
  • AI navigates naturally (pattern-based)
