# minimal and complete

## Spec

Try to be complete with the minimal of means, knowing it will probably fall short and need continued effort.

For situations where:
- Complete may not be fully known
- Complete may not be achievable
- Don't waste time and complexity where it won't pay off

Question every addition - is this needed NOW? Simplicity paramount.

Scope: Global.

Purpose: Default mode for building new things. Get started without over-engineering, evolve based on evidence.

## Self-eval

- [ ] Minimal means used
- [ ] Completeness attempted (not avoided)
- [ ] Accepts shortfall as natural
- [ ] Avoids wasted complexity

## Comments

Contrast with sufficient and complete (prefer overlap over gaps - for capture/documentation).
