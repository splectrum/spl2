**Type:** plain req

# commit message

## Spec

Headline for a git commit - enough to identify and find context, detail lives in assets.

Should:
- Identify what's being committed (scope/area)
- Summarize why (purpose, not mechanics)
- Hook to detail (reference DAILY_LOG, project, etc.)

Should NOT:
- Be a changelog
- Explain the diff
- Duplicate what's in assets

Scope: Global.

Purpose: Table of contents entry - find and understand context, seek detail elsewhere.

## Self-eval

- [ ] Identifies scope/area
- [ ] Summarizes purpose
- [ ] Hooks to detail where appropriate
- [ ] Does not duplicate asset content
- [ ] Readable at glance

## Comments

Follows headline/detail separation pattern. Commit message is headline, assets are detail.
