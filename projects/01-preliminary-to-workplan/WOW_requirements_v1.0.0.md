**Created:** Project 01 (preliminary-to-workplan)
**Version:** 1.0.0

Requirements for Ways of Working documentation using TDC validation framework.

---

## Purpose

WOW.md documents how human and AI collaborate, what methodologies we use, and our working philosophy. It must enable effective collaboration and autonomous AI decision-making.

---

## Success Criteria

WOW documentation passes validation when it satisfies all the following tests:

### 1. Fresh Context Test
**Requirement:** A new session with no prior context should understand:
- How human and AI collaborate (roles, decision-making, boundary model)
- What methodologies we use (PRINCE2, TDC)
- Working philosophy and principles
- How methodology evolves

**Validation:** Read docs with no context. Can you understand how to work together?

### 2. Decision-Making Test
**Requirement:** When facing collaboration questions, the docs must clarify:
- What AI decides autonomously
- What requires human input
- What we collaborate on
- Boundary between human and AI responsibility

**Validation:** Present hypothetical collaboration scenarios. Do docs guide to right answer?

### 3. Consistency Test
**Requirement:** Documentation must be internally consistent
- No contradictions between Philosophy and methodologies
- PRINCE2 and TDC integration clear
- Roles align with philosophy

**Validation:** Cross-reference all statements. Any conflicts?

### 4. Completeness Test
**Requirement:** No critical gaps that would cause:
- Misaligned collaboration expectations
- Confusion about roles or methodologies
- Missing context for how we work
- Inability to start collaborative work

**Validation:** Identify gaps that would block or misdirect collaboration.

### 5. Simplicity Test
**Requirement:** Documentation should be:
- As concise as possible while remaining complete
- No unnecessary complexity
- Clear, direct language
- Well-structured and scannable

**Validation:** Can any section be simplified without losing critical information?

### 6. Actionability Test
**Requirement:** Documentation must be actionable:
- Concrete enough to guide real collaboration
- Not too abstract or theoretical
- Clear working patterns

**Validation:** Can you act on what's documented, or is it too vague?

### 7. Reality Alignment Test
**Requirement:** Documentation matches actual working relationship:
- Describes what we really do
- Reflects actual collaboration patterns
- Philosophy is genuinely lived (not aspirational)

**Validation:** Does this match how we actually work?

### 8. Structure Test
**Requirement:** Information is well-organized:
- Easy to find what you need
- Logical flow and grouping
- Right level of detail (headline vs detail files)

**Validation:** Can you quickly find relevant information when needed?

---

## Scoring: Red/Yellow/Green

### 🟢 Green - Fit for Purpose
- Requirements met adequately
- No blocking issues
- Enables effective collaboration
- Good enough to use

### 🟡 Yellow - Issues Present
- Partially met, with concerns
- Issues may cause confusion
- Work can proceed but harder than necessary
- Should improve but not blocking

### 🔴 Red - Blocking Issues
- Fails significantly
- Critical gaps or contradictions
- Would block or misdirect collaboration
- Must fix before usable

---

## Overall Assessment

WOW documentation is "good enough" when:
- No Red scores remain
- Yellow scores are acceptable trade-offs
- Can start effective collaborative work
