# CIP Processing

**Priority:** High
**Type:** Explorative Project
**Dependencies:** None (can run anytime)
**Source:** Status observation - 15 active CIPs accumulated

---

## Overview

Process accumulated CIPs to create backlog items, update foundations, spawn new CIPs, and close implemented ones. Standard maintenance project triggered when CIP count indicates processing needed.

---

## Trigger Conditions

**When to spawn this project:**
- CIP count exceeds threshold (e.g., 10+ unprocessed)
- Significant CIPs blocking other work
- Planning cycle needs clear backlog
- Status review indicates CIP debt

**This is a standard project** - can be dropped into backlog whenever CIP processing is needed.

---

## Scope

### Processing Activities

For each CIP:
1. **Review** - Understand full scope
2. **Assess** - Priority, dependencies, effort
3. **Process** - Create outputs per CIP's processing guidance
4. **Update** - Move to Implemented/Rejected/keep Active

### Typical Outputs

- Backlog items created
- Foundation docs updated
- Design docs created/updated
- New CIPs spawned
- Requirements created
- Glossary terms added

## Success Criteria

1. All CIPs reviewed and assessed
2. Processing guidance followed for each
3. Backlog items created with dependencies mapped

## Approach

**Twin pair methodology:**
- Pair 1: CIP review/assessment + backlog items
- Pair 2: Foundation updates + design docs

**Or sequential processing:**
- Process CIPs in priority order
- Create outputs as we go
- May be more practical for varied CIP types

- This is a **repeatable standard project** - use whenever CIP debt accumulates
- Can be time-boxed (e.g., "process top 5 CIPs")

- Processing doesn't mean implementing - it means creating actionable backlog items
